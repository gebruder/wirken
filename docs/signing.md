# Signing

Wirken uses Ed25519 across three independent signing surfaces: per-instance audit chain-head signing, per-skill bundle signing, and offline release signing of the binary distribution. Each surface has its own keypair, file location, and verification call site; no single key signs across surfaces.

## Chain-head signing

Per-instance signing of `ChainHead` records bracketing session start/end and cadence checkpoints. The signing key is generated lazily on first use, stored owner-only on disk, and never leaves the gateway process.

- **Key material.** Ed25519, raw 32-byte seed. Stored at `<data_dir>/audit/audit-signing.key` (mode 0o600 on Unix). Public counterpart at `<data_dir>/audit/audit-signing.pub`. Generated by `AuditSigningKey::load_or_create` at first call; subsequent calls re-read the existing files. See `crates/audit/src/signing.rs:78-110`.
- **Canonical message format.** Length-prefixed, schema-versioned. Domain separator `"wirken/audit-chain-head/v1\0"`, schema version `2`. Full layout and field-by-field byte budget are in [audit-events.md](audit-events.md#chain-head-signing).
- **Verification call site.** `wirken sessions verify` and `wirken audit verify` recompute the message bytes from the row's `(seq_start, seq_end, prev_hash, hash, schema_version)` tuple and verify the signature with `ed25519_dalek::verify_strict` against the recorded `signing_pubkey`. Source: `crates/audit/src/signing.rs:189-208` (`build_signed_message`) and `crates/audit/src/session_log.rs` `verify_signatures` (the `verify_strict` call).

## Skill signing

Per-skill bundle signing with a composite signature scope. The signature covers `SKILL.md` plus `skill.wasm` when present; sibling files outside that pair are not in scope.

- **Composite hash layout.** When `skill.wasm` exists: `sha256(SKILL.md_bytes || 0x00 || skill.wasm_bytes)`. When it does not: plain `sha256(SKILL.md_bytes)`. The null-byte separator prevents a trailing null in `SKILL.md` from hashing identically to a preceding empty wasm. Source: `crates/gateway/src/skill_registry.rs:218-233` (`hash_skill_bundle`).
- **Sign call.** `wirken skills sign <dir>` signs the composite hash with Ed25519 and writes the signature as hex to `<dir>/SKILL.sig`, plus the public key to `<dir>/SKILL.pub`. Source: `crates/gateway/src/skill_registry.rs` (`sign_skill`).
- **Delegated sign call.** `wirken skills sign --root-key <offline-root-seed> <dir>` additionally binds the signer key to an operator registry root: it writes `SKILL.deleg`, the root's signature over the signer's public key, so the bundle verifies under a configured root (strict load). The root private seed is read from the given path in the operator's offline signing environment and is never written back. For bundled skills, `install_bundled_skills_delegated` does the same for a fresh per-skill signer; with no root, `install_bundled_skills` self-signs as before. Source: `crates/gateway/src/skill_registry.rs` (`delegate_sign_skill`), `crates/agent/src/bundled_skills.rs` (`install_bundled_skills_delegated`).
- **Key material.** Per-author signing key at `<data_dir>/signing-key.hex` (hex-encoded Ed25519 seed, mode 0o600 on Unix). Generated on first `wirken skills sign` invocation if absent. See `crates/cli/src/commands/skills.rs:205-237`.
- **Verification at install.** `wirken skills install` calls `verify_skill_with_expected_key_and_delegation` against the registry-supplied `signer_key`. When the binary embeds a non-empty `wirken-registry-pubkey.pub` at build time, the registry-supplied key must also carry a `signer_key_delegation` signature by the bundled root. Source: `crates/gateway/src/skill_registry.rs:261-353`.
- **Verification at load.** Every `SkillLoader::load_file` call runs the signature gate first, on the raw on-disk bytes, before any frontmatter parse, path templating, or binary probe. The gate branches on whether an operator registry root is installed. With **no root** (the default floor), it runs `verify_skill_self_signed` against the on-disk `SKILL.sig` and `SKILL.pub`; a bundle with no `SKILL.sig` is refused unless `WIRKEN_ALLOW_UNSIGNED_SKILLS=1` (warn on stderr and proceed), and a present-but-bad signature is always refused. With a **root configured** (strict), it runs `verify_skill_delegated`: the signer (`SKILL.pub`) must be delegated by the root via `SKILL.deleg`, and the bundle signature must verify under that signer. A self-signed-only bundle (no `SKILL.deleg`) and an unsigned bundle are both refused; the unsigned bypass does not apply once a root is set. A root file present but unparseable is fail-closed. Source: `crates/agent/src/skill.rs` (`verify_skill_signature`, `verify_skill_signature_with_root`), `crates/gateway/src/skill_registry.rs` (`verify_skill_self_signed`, `verify_skill_delegated`, `load_registry_root`).
- **Bypass.** `WIRKEN_ALLOW_UNSIGNED_SKILLS=1` skips the signature requirement for bundles with no `SKILL.sig` / `SKILL.pub`. A bundle with an invalid signature is never accepted under this bypass. Listed in the [security-properties escape-hatch table](security-properties.md#documented-escape-hatches).
- **Operator registry root (opt-in identity anchor).** `wirken skills trust-root <pubkey-hex>` installs an operator-controlled Ed25519 root public key at `<data_dir>/registry-root.pub`. The file is integrity-sensitive, not secret: mode `0o644` on Unix (owner-write, world-read), so a non-owner process cannot replace the anchor while any reader may verify against it. This is runtime operator state, separate from the compile-time `wirken-registry-pubkey.pub` placeholder. The matching root **private** key never ships with wirken and never lands on the gateway host; it signs per-skill signer-key delegations offline in the operator's signing environment. The load gate resolves the root from the same `default_data_dir()` the gateway's `GatewayConfig` uses, so the gate and the running gateway never look in different directories. Source: `crates/gateway/src/skill_registry.rs` (`save_registry_root`, `load_registry_root`, `registry_root_path`), `crates/gateway/src/config.rs` (`default_data_dir`).
- **Absent vs corrupt root.** Absent is the intended default: no root file means the self-signed floor, and skills load normally. A root file that is present but unparseable is a misconfigured strict anchor and is fail-closed: it refuses every skill and surfaces distinctly as `AgentError::RegistryRootUnusable` at error level, so a fat-fingered `trust-root` hex reads as "root is corrupt" rather than a silent no-skills-load that looks like the floor failing. Source: `crates/agent/src/skill.rs` (`load_dir` error-level surfacing), `crates/agent/src/error.rs` (`RegistryRootUnusable`).
- **Revocation and containment.** The presence of the root file is revocable by anyone with gateway-UID write, so the file is not the anchor — the offline private key is, and what the file does is opt the loader into demanding delegation from it. Deleting the file downgrades strict back to the self-signed floor; it does not grant anything. An attacker who removes it reverts to the floor but cannot forge a delegated bundle, because that needs the root private key that never ships, and the floor still rejects unsigned and invalid bundles. The worst the deletion buys is acceptance of a self-signed bundle the attacker must also plant — two host-write actions on a host where they already hold gateway-UID write. That is a containment statement, not a gap.

The precise public claim this supports: **skills are tamper-evident by default and identity-anchored when an operator configures a root, with the root key held offline.** That sentence is true against the code as merged; it should not be rounded up to "identity-anchored" unqualified.

## Release signing

Offline maintainer signing of release artifacts. The maintainer's private key is held outside the repo tree; the public key is embedded in `install.sh` and pinned in `KEYS`.

- **What gets signed.** `checksums.sha256`, signed with `ssh-keygen -Y sign` to produce `checksums.sha256.sig`. The release-build CI produces both files alongside the platform binaries on every `v*` tag.
- **Verification at install.** `install.sh` fetches both files, verifies the signature with `ssh-keygen -Y verify` against the embedded public key, then verifies the binary's SHA-256 against the signed checksums file. Every failure path is fail-closed: missing signature, missing checksum, mismatched digest, missing local `sha256sum`/`shasum`, all abort the install. The documented opt-out is `WIRKEN_ALLOW_UNVERIFIED=1` at install time only.
- **Trust anchor.** The Ed25519 public key embedded in `install.sh` is also pinned in `KEYS` (top-level) and listed by fingerprint in `SECURITY.md`. Rotation is a three-step procedure that swaps the trust anchor in one commit and immediately cuts a new release signed with the new key.
- **Detail.** The full maintainer runbook lives in [release-process.md](release-process.md); the cryptographic rationale and rotation/recovery procedures in [release-signing.md](release-signing.md).
